Building Exvius Revival Desktop from source
===========================================

The package has three built parts. All three were built on Linux (Ubuntu 24.04).

1. runner\game.elf  (source\guest)
   A static 64-bit ARM Linux program. It loads the game's libgame.so, stands in for the parts of
   Android the library calls (the C library differences, JNI and the Java helpers, OpenSL ES, the
   asset manager, text drawing), and passes graphics, sound, network and input to the runner.
     needs:  gcc-aarch64-linux-gnu, stb (libstb-dev, for stb_truetype.h)
     build:  sh source/guest/build.sh          -> build/game.elf

2. runner\runner.exe  (source\runner)
   Runs game.elf: an ARM64 processor (dynarmic), the Linux system calls game.elf makes, all of its
   threads scheduled on a few host threads ("cores": the game's main thread on one, the rest
   sharing the others), OpenGL ES 2 passed to desktop OpenGL, SDL2 for the window,
   input and sound, and plain HTTP to the local server.
     needs:  mingw-w64 (the "posix" thread variant: x86_64-w64-mingw32-gcc-posix / g++-posix),
             SDL2 development files for mingw (SDL2-devel-2.x-mingw), cmake, ninja,
             dynarmic from https://github.com/azahar-emu/dynarmic with its submodules, built as
             static libraries for Windows, and Boost headers.
     two small changes to dynarmic were needed:
       - src/dynarmic/frontend/A64/translate/impl/system.cpp: treat CNTVCT_EL0 like CNTPCT_EL0
         (the game library reads the virtual counter);
       - externals/xbyak/xbyak/xbyak_util.h: older mingw headers lack three fields of
         SYSTEM_LOGICAL_PROCESSOR_INFORMATION_EX (EfficiencyClass, GroupMasks, GroupCount).
     build:  sh source/build_windows.sh        -> build/windows/runner.exe, SDL2.dll
             (DYN = dynarmic source, DB = its Windows build folder, SDL = the mingw SDL2 folder)
     The same source builds for Linux with build_linux.sh, which is how most of it was tested.
     runner/gl_names.h and gl_gen.inc are generated by tools/gen_gl.py.

3. "Exvius Revival Desktop.exe"  (source\stub\stub.c)
     build:  x86_64-w64-mingw32-gcc-posix -O2 -municode -mwindows -o stub.exe stub.c

pack.sh puts the package together: the three parts, Python 3.12 for Windows
(python-build-standalone, "install_only" build) with the server's packages (cryptography, PyYAML,
tzdata, Pillow), the launcher (app\), and the server. The server is not part of this source: it
is the engine of Exvius Revival for iOS, https://github.com/CreamySeaman6/Exvius-revival-ios, and
pack.sh copies it from a checkout of that repository (source/server, ios-server/serve.py,
ios-server/fetch_data.py, ios-server/docker-compose.yml, data/latest.json and its README):
     DEV=<checkout of Exvius-revival-ios> OUT=dist/ExviusRevivalDesktop sh pack.sh
The commit it was taken from is written to server\REVISION.txt in the package.

Debugging aids in the runner and game.elf (environment variables)
  FFBE_VERBOSE=1, VERBOSE=1      detailed log in client\runner.log (2 = also file opens)
  FFBE_CONTROL=<folder>          test control: write a file "cmd" there with lines such as
                                 "tap 320 500", "key back", "shot name", "quit"
  FFBE_AUDIO_DUMP=<file>         write the mixed sound (48 kHz stereo 16-bit) to a file
  TRACE_FUNCS=sym,sym+r,@hex+r   log calls of game-library functions (arguments, text they point
                                 at, and with +r the return value); @hex is an offset in libgame.so
  FFBE_WINDOW=WxH                window size
  FFBE_CORES=N                   processor cores for the game (1 = everything on one host thread)
  FFBE_OVERLAY=<folder>          the server's data/native folder: the game reads those files in
                                 place under game/files instead of downloading copies
  FFBE_AUDIO_RESERVE=ms          sound collected before a stream starts playing (default 60)
  FFBE_VOLUME=percent            master volume
  FFBE_TOUCH_LOG=1               log every touch the game is given (down, move, up) with its frame
  With FFBE_VERBOSE=1 the runner logs every 5 seconds: frames shown, frames that came late
  (more than 25 ms after the one before), the longest frame, sound gaps (a playing stream that
  ran dry and then carried on) and the least sound any stream had in hand.
